# MAA Copilot 作业制作手册

把参考视频、口播攻略或一张地图截图，翻译成一份能在 MAA 里稳定复现的 Copilot JSON。

本仓库不是“作业合集”，而是一套可复用的制作与验收方法：先建立正确参照系，再核对地图格型，再对齐账号实际技能，最后用单变量试跑归因。配套案例是《明日方舟》OS-EX-8 突袭 5 人摆完挂机作业。

## 这份手册解决什么问题

- 视频字幕只给“桃子↓、初雪→”，不给精确坐标和朝向。
- 地图上有大量不能部署的装饰格，肉眼看起来像高台或地面。
- 作业里写的 `skill` 编号，和账号实际携带的技能不一致。
- 技能轴写错，阵法术师不开技能就几乎不输出。
- 一次改坐标、朝向、技能三个变量，失败后不知道是哪一个出错。
- MAA 显示“任务完成”，但游戏其实只是动作链跑完，不等于三星通关。

## 快速开始

1. **选参照系**：优先用 MAA 自己生成的 `debug/map/*.jpeg` 做坐标底图；没有时再用 PRTS.Map 的 MAA 坐标模式。不要混用普通地图坐标和 MAA 坐标。
2. **查格型**：读关卡 tile JSON，确认每个落点的 `buildableType` 和 `heightType`。`0` 永远不能部署。
3. **对技能**：在游戏里逐个点开干员卡，确认实际携带的技能序号；作业里的 `skill` 必须与它一致。
4. **写动作**：按“部署 → 技能 → 再部署”的顺序写 `actions`；需要手动轴的干员用 `skill_usage: 0` 加显式 `Skill` 动作。
5. **先演习再实战**：第一次跑用演习模式；只改一个变量；失败后先看 `asst.log` 和 `debug/map`，不要凭感觉重写。

## 核心方法：四道闸门

### 第一道：参照系闸门

同一张地图至少有三套坐标语言：游戏网格、PRTS.Map 普通坐标、MAA `location`。混用是坐标错误的头号原因。

- MAA 坐标约定：`location: [x, y]`，`x` 从左往右从 0 开始，`y` 从上往下从 0 开始。
- 最可靠的底图是 MAA 实战生成的 `debug/map/<时间>_<stage>.jpeg`，上面直接带坐标网格。
- 用视频抽帧只做“相对位置”和“顺序”的参考，不拿它直接量坐标。
- 一旦发现同一张图两套坐标对不上，立即停下来重新标定，不要继续“试一格”。

### 第二道：格型闸门

每个落点先过 tile JSON，再写进作业。

- `buildableType: 0`：不可部署。无论等多久、换朝向都不会落地。
- `buildableType: 1`：近战位，一般是 `tile_road`。
- `buildableType: 2`：远程位，一般是 `tile_wall`。
- `heightType: 0`：地面；`heightType: 1`：高台。
- `tiles` 是 `tiles[y][x]` 的二维数组，读取时不要先 x 后 y。

建议把每个落点写成一行核对记录：

```text
凛御银灰  (6,6)  type=1  height=0  Down
结城理    (1,4)  type=1  height=0  Up
圣聆初雪  (10,3) type=2  height=1  Down
遥        (10,2) type=2  height=1  Down
斩业星熊  (3,1)  type=1  height=0  Right
```

### 第三道：账号状态闸门

作业是“给账号看的”，不是给视频看的。

- 同一个干员可能带 1/2/3 技能，技能编号不同，轴完全不同。
- 阵法术师类干员通常不攻击，只有开技能后才输出；如果作业写的是自动开技能、账号带的却是长轴手动技能，前期会几乎零输出。
- `skill_usage` 语义：
  - `0`：不自动使用，完全依赖 `actions` 里的 `Skill`。
  - `1`：好了就用。
  - `2`：用指定次数，配合 `skill_times`。
  - `SkillDaemon` 只对 `skill_usage: 1` 的干员持续生效。
- 战斗卡序里的 `unknown oper N` 指的是“第 N 张战斗卡”，不是你以为的那个干员。先核对卡序，再改名字。

### 第四道：单变量闸门

失败一次只改一个变量，否则无法归因。

推荐顺序：

1. 先只改坐标；
2. 坐标全对后，再改朝向；
3. 朝向全对后，再改技能序号；
4. 技能序号全对后，再改技能时机；
5. 最后才动阵容替换。

每次改动前备份旧 JSON，每次试跑记录时间、taskid、失败现象和改动点。

## 首跑十条硬校验

在点“开始”之前，逐条过一遍：

1. `stage_name` 与关卡 ID 完全一致。
2. 突袭作业写 `difficulty: 3`，普通写 `difficulty: 1`。
3. 每个 `Deploy` 落点的 `buildableType` 都不是 `0`。
4. 每个 `direction` 都不会让干员朝地图边缘外攻击。
5. 干员名与游戏内名称完全一致，不用简称、皮肤名、外号。
6. 每个 `skill` 编号与账号实际携带的技能一致。
7. 该自动的写 `skill_usage: 1`，该手动的写 `0` 并配显式 `Skill`。
8. 第一次部署的费用足够，不会因为卡费导致动作跳过。
9. 第一次试跑用演习模式，不消耗理智。
10. 跑完不只看“任务完成”，要看到结算三星或至少确认战斗胜利。
