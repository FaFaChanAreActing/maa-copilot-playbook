# 案例：OS-EX-8 突袭 5 人摆完挂机

## 1. 目标

把 B 站参考视频《5人OS-EX-8突袭摆完挂机 简单好抄高容错》转成一份 MAA Copilot JSON，要求：

- 5 人编队；
- 摆完后续技能自动托管；
- 突袭难度；
- 坐标、朝向、技能轴可复现。

参考视频：<https://www.bilibili.com/video/BV1gTy3zVEvc/>

## 2. 视频给出的信息

字幕顺序：

```text
桃子↓ → 结城理↑ → 圣初雪→
→ 理哥A两下怪开技能
→ 部署遥↓ → 斩业星熊→
→ 遥暖机后挂机到结束
```

替换说明：

```text
理哥换乌尔比安：先在他位置放斩业星熊，歌蒂放遥左边朝左。
```

这些信息只够确定“顺序 + 大致朝向”，不够确定坐标。坐标必须另行核对。

## 3. 编队与技能

| 作业中的干员 | 替代关系 | 技能 | `skill_usage` |
|---|---|---|---|
| 凛御银灰 | 替代桃金娘 | 2 | 1 |
| 结城理 | 无 | 3 | 0 |
| 圣聆初雪 | 无 | 2「霜涛覆岭」 | 1 |
| 遥 | 无 | 2「幽隙栖萤」 | 1 |
| 斩业星熊 | 无 | 2 | 1 |

关键点：**初雪必须带 2 技能**。如果账号带的是 3 技能「群山俯首」，它是长轴手动技能，和这套“摆完挂机”的节奏不一致，会出现“干员都落地了但前期几乎没有输出”。

## 4. 坐标

地图 13×9，`tiles[y][x]`。五个落点全部通过 tile JSON 校验：

| 干员 | location | `buildableType` | `heightType` | direction |
|---|---|---|---|---|
| 凛御银灰 | `(6,6)` | 1 | 0 | Down |
| 结城理 | `(1,4)` | 1 | 0 | Up |
| 圣聆初雪 | `(10,3)` | 2 | 1 | Down |
| 遥 | `(10,2)` | 2 | 1 | Down |
| 斩业星熊 | `(3,1)` | 1 | 0 | Right |

### 4.1 遥与初雪的上下关系

两人都在右侧高台，且相邻：

```text
遥       (10,2)  ← 上层
圣聆初雪 (10,3)  ← 下层
```

不要把两人上下放反。初雪在下层如果朝右，攻击范围会大量落到地图外；本作业用 `Down`，并把遥放在她正上方。

### 4.2 已确认不可用的格子

| 格子 | 实际类型 | 现象 |
|---|---|---|
| `(4,4)` | `buildableType: 0`，`tile_floor` | 看起来像地板，实际不能部署 |
| `(2,6)` | `buildableType: 0`，`tile_forbidden` | 等多久都不会落地 |
| `(6,5)` | `buildableType: 0` | 不可部署 |
| `(6,4)` | `buildableType: 0`，`tile_end` | 不可部署 |

这些格子是最容易让人误以为“再等等就能放”的坑。

## 5. 动作序列

```json
[
  { "type": "SpeedUp" },
  { "type": "Deploy", "name": "凛御银灰", "location": [6, 6], "direction": "Down" },
  { "type": "Deploy", "name": "结城理", "location": [1, 4], "direction": "Up" },
  { "type": "Deploy", "name": "圣聆初雪", "location": [10, 3], "direction": "Down" },
  { "type": "Skill", "name": "结城理", "pre_delay": 2400, "timeout": 10000 },
  { "type": "Deploy", "name": "遥", "location": [10, 2], "direction": "Down" },
  { "type": "Deploy", "name": "斩业星熊", "location": [3, 1], "direction": "Right" },
  { "type": "SkillDaemon" }
]
```

`结城理` 不能设成 `skill_usage: 1`。字幕里的“理哥 A 两下怪开技能”是一个明确的手动时间点，所以：

- `skill_usage: 0`；
- 在初雪部署后插入显式 `Skill`；
- `pre_delay: 2400`，`timeout: 10000`；
- 其余四人 `skill_usage: 1`，最后由 `SkillDaemon` 托管。

## 6. 这次踩过的坑

### 6.1 把不可部署格写成落点

第一版把 `(4,4)`、`(2,6)` 当成可部署格。MAA 日志显示执行了 `Deploy`，但游戏里干员一直不出现。查 tile JSON 后确认：

```text
(4,4) = buildableType 0, tile_floor
(2,6) = buildableType 0, tile_forbidden
```

结论：**落点必须先过 tile JSON，不能靠地图截图猜。**

### 6.2 `unknown oper 2` 不是初雪

日志里的 `unknown oper 2` 指“战斗卡序第 2 张”，不是“初雪”。旧版第 2 张实际是遥，早期把锅扣在初雪皮肤上是错误归因。

结论：**先核对战斗卡序，再改干员名。**

### 6.3 初雪技能序号不一致

作业写 `skill: 2`，账号实际带 3 技能「群山俯首」。阵法术师不开技能不攻击，导致 40 秒只有 3/72 击杀，生命值从 3 掉到 1。

结论：**作业里的 `skill` 必须和账号实际携带一致；长轴手动技能不能套用自动托管轴。**

### 6.4 遥与初雪放反

早期版本把初雪放在 `(10,2)`、遥放在 `(10,3)`，与参考作业和截图相反。修正为：

```text
遥       (10,2)
圣聆初雪 (10,3)
```

结论：**相邻高台的双干员，必须用截图/参考作业交叉确认上下关系。**

### 6.5 一次改多个变量

坐标、朝向、技能同时改，失败后无法判断是哪一项生效。后续改成单变量修正：

```text
坐标 → 朝向 → 技能序号 → 技能时机
```

## 7. 替代方案

如果不用结城理，而用乌尔比安：

1. 先在结城理原位放斩业星熊；
2. 歌蕾蒂娅放在遥左侧，朝左；
3. 重新确认阻挡位和技能轴。

这条替代路线来自视频字幕，但本作业没有启用，需要单独试跑。

## 8. 验收记录

本地 MAA 已按上述动作链完成一轮 Copilot 执行，动作顺序与日志一致：

```text
Deploy 圣聆初雪 → UseSkill 结城理 → Deploy 遥 → Deploy 斩业星熊 → SkillDaemon
```

上站前仍建议按你的账号在演习模式再跑一次，确认：

- 五个干员全部落地；
- 初雪实际携带 2 技能；
- 结城理第一次技能在部署初雪后开启；
- 战斗结算为胜利/三星。
